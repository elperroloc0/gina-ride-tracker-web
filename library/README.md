# Библиотека компонентов — Gina's Ride Tracker

15 самостоятельных HTML-превью, по одному на компонент. Это исполняемая версия
`../DESIGN-SYSTEM.md`: там правила текстом, здесь — те же значения, которые можно
открыть и посмотреть. Значения вынуты из артбордов, не придуманы заново.

Все токены объявлены в каждом файле как CSS custom properties — файл открывается
сам по себе, без сборки и без общего стиля.

## Как залить в Claude Design

Требуется вход на claude.ai и политика организации, разрешающая Claude Design.

1. **Один раз, в интерактивной сессии Claude Code на этой машине:**

   ```
   /design-login
   ```

   Headless- и SDK-запуски после этого переиспользуют авторизацию. В
   неинтерактивной сессии команда не работает — это не обходится.

2. **Проект-приёмник должен быть типа design system.** Тип задаётся при создании
   и потом не меняется: пуш в обычный проект не превратит его в дизайн-систему.
   Либо выбрать существующий, либо создать новый.

3. **Синхронизация:**

   ```
   /design-sync
   ```

   Заливка инкрементальная, по компоненту — не «заменить всё целиком».

## Маркер `@dsCard`

Первая строка каждого файла:

```html
<!-- @dsCard name="Color tokens" group="Foundations" subtitle="..." width="1080" height="900" -->
```

По этим маркерам витрина Design System собирает индекс карточек.

Оговорка: документирован только атрибут `group`. Остальные — `name`, `subtitle`,
`width`, `height` — выведены по форме устаревшего `register_assets`, который брал
ровно эти поля. Если витрина не подхватит карточки автоматически, работает
явная регистрация через `register_assets` с теми же значениями.

## Артборды сюда не переносятся

Семь экранов в `../` живут в раннем превью редактора Claude Design, вшитом в
артефакт. Импорта и экспорта между ним и claude.ai/design нет ни в одну сторону.
Экраны либо пересобираются там заново, либо переносятся как референс: в тулбаре
канваса есть Export PDF (все артборды одним файлом) и Export PNG (по артборду).
